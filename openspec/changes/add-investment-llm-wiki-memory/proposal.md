## Why

当前 DeerFlow 研究运行关闭了内建记忆，每次运行使用新的 thread ID；网页对话主要留在浏览器本地。Agent 无法可靠地跨会话记住投资偏好、研究进度和历史决策，也无法按天回顾并整理这些信息。需要一个按用户隔离、可检索、可过期的投资记忆空间，使每日建议能引用近期对话和经确认的长期偏好。

## What Changes

- 为每位用户建立独立的 `llm-wiki`，用短期、长期、每日归档和按天保存的 session 组成分层记忆；每层目录都有 `index.md`、`log.md`、`readme.md`。
- 服务端持久化每个 session 的逐日对话与摘要，让当天不同 session 共享当天信息；历史跨 session 召回以 daily 日志为主，不向投研 Agent 暴露原始 session 文件。
- 增加每日定时归档、手动归档、重跑补档、候选记忆晋升和冲突处理；利用频率、跨日/跨会话证据、基础程度、抽象程度和来源可信度决定短期或长期。
- 在账户设置提供原始 session 和归档记忆的保留期限：前者最多 30 天，后者最多 365 天；提供归档状态、手动触发与用户记忆查看/更正/删除。
- DeerFlow 通过按用户授权的记忆检索接口取得有来源的片段。记忆仅提供用户上下文，行情、财务、资产金额和交易状态仍从项目的权威数据层查询。

## Capabilities

### New Capabilities

- `investment-memory-wiki`: 用户空间、会话捕获、每日归档、分层记忆、召回、留存设置与治理的完整行为契约。

### Modified Capabilities

无。仓库目前没有 OpenSpec 主规格；现有 `kitty-specs` 保留，实施时另行同步受影响的既有规格。

## Impact

- 服务端：身份/账户设置、对话会话 API、DeerFlow worker/工具适配、持久化和后台定时作业。
- 前端：服务端会话列表、账户设置中的记忆期限与归档操作、记忆浏览和更正。
- 数据：每用户的私有 Markdown wiki、短期原始会话、归档索引和作业状态；迁移现有浏览器本地会话时需征得用户选择。
- 运维：共享持久卷、备份/恢复、到期删除、失败补档、跨用户隔离测试。
