# 投研记忆与 llm-wiki

投研对话由服务端分配 session ID，按 Asia/Shanghai 消息日期保存。每位账号在 `DATA_DIR/llm-wiki/users/<owner-id-hash>/` 有独立 wiki。根目录、`sessions`、`daily`、`short-term`、`long-term` 及日期子目录都含小写 `index.md`、`log.md`、`readme.md`。MySQL 保存身份、消息、归档状态、条目与文件哈希；Markdown/JSONL 是可读投影，不作为行情、资产或订单账本。AI 投研聊天页顶部的「投资记忆」打开 Markdown 文件浏览器；Docker 部署时目录位于 `agent-data` 数据卷内的 `/app/data/llm-wiki/users/<owner-id-hash>/`。

## 使用

- 聊天列表从服务端恢复。旧浏览器会话只在用户于头像菜单「记忆保留期限」选择导入后进入服务端；导入记录标为 `legacy`，不自动提升为投资偏好。
- 聊天粘贴图片后立即进行视觉解析；原图、名称、尺寸、字节数、SHA-256 与解析文本按账号和会话保存在 MySQL。后续同会话提问读取解析文本；导入持仓时可复用原图。删除会话及原始会话到期会清理对应图片。
- 头像菜单「记忆保留期限」管理当前账户的原始 session 留存 1–30 天、日报及长期记忆留存 1–365 天，默认 30/365 天。短期条目最多保留 30 天，也受较短的归档期限约束。缩短期限立即清理；服务启动先清理恢复数据，再开放请求。
- 聊天页「投资记忆」展示 wiki 的目录、Markdown 文件、日报版本和来源元数据。当前日报可编辑并生成新版本；短期和长期记忆正文编辑会同步数据库与 Agent 召回；会话日摘要的议题部分可以修改。`index.md`、`log.md`、`readme.md` 也可编辑；已发布的历史日报版本保持只读。文件保存使用 SHA-256 冲突检查。该页面可手动归档日期或刷新目录。删除会话会使受影响日报退出召回并排队重算，仅由该会话支持的条目同步撤销。
- 每天 03:00（Asia/Shanghai）归档前一日；重启后补跑。当天手动归档为 `provisional`，新消息会使该版本失效，次日自动生成最终版本。无对话日是 `empty`。模型不可用时使用有来源的主题级 `degraded` 摘要，明确标注缺口。

## 召回与建议

Agent 可以读取当前会话最近对话、当天其他会话的派生摘要、已发布 daily 和长短期条目。过去的原始 session JSONL 与逐轮消息不提供给记忆工具。每条召回带层级、时间、状态和来源，近期 daily 与短期优先；重复的稳定偏好需至少跨两日、三个会话才会形成 `inferred` 长期候选。用户明确表达的长期风格可直接记为 `explicit`；用户更正为 `confirmed`。推断候选不能直接充当仓位或交易授权。

记忆仅解释历史交流。Agent 给出每日买入、加仓、持有、减仓、卖出或观望建议时，必须重新查询当前行情与账户数据，并说明数据时点、触发/失效条件和缺口。账户读取仍需本轮明确选择；记忆工具不能下单。

## 运维、备份与恢复

`./scripts/docker-backup.sh` 保存 MySQL SQL 转储，并在 wiki 存在时额外保存同名前缀的 `-llm-wiki.tar.gz`。两份文件应作为一组加密保存。恢复时先恢复 MySQL 和 `agent-data` 卷里的 `llm-wiki`，再启动 Web；启动清理会按每账号当前期限移除过期消息与投影。缺失的 session JSONL 可由有效 MySQL 消息重建；已过原文期限的日报应从对应 wiki 备份恢复，不能再凭已删除原文生成。

可在设置页查看归档状态；接口路径为 `/api/v1/ai/memory/settings`、`/archive`、`/archive-jobs/{YYYY-MM-DD}`、`/daily`、`/entries`。作业按账号和日期持久化，发布版本由 MySQL 与 SHA-256 文件 manifest 一起校验；`failed` 作业可重试，上一份同输入的完整版本仍可读。归档或检索降级时，Agent 会显示记忆未加载，不以旧记忆冒充实时数据。
