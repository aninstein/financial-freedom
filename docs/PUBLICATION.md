# 公开发布前核对

当前源码快照已排除本机 `.env`、数据库、日志、审计截图与备份。公开来源的 DeerFlow 固定版本归档保留在 `vendor/deerflow/`，校验值见 `provenance.json`。`.gitignore` 只影响后续提交，不会删除旧提交里的内容。不要把当前仓库的既有 Git 历史直接设为公开；请从干净源码快照创建全新的仓库历史，并使用适合公开的提交者姓名与邮箱。

发布步骤：

1. 在当前工作树运行 `python3 scripts/check-staged-secrets.py --worktree`，复核所有要发布的文件及数据源使用条款。
2. 只复制 Git 当前索引内的源码文件到全新目录；不要复制 `.git`、`.env`、`data/`、`.runtime/`、`artifacts/` 和备份。
3. 在全新目录初始化 Git，检查 `git status` 与首个提交的作者、邮箱，再连接公开远端。不要将旧分支合并或推送到新仓库。
4. 如果旧提交或旧备份曾对外可见，轮换其中可能出现的凭据，并核对数据库中的私人资料是否需要通知或进一步处理。

许可见根目录 `LICENSE`。商业用途未获授权，因此发布时应描述为“源码可见、非商业使用”，避免标为 OSI 开源许可。
