# Agent 运行时选型与迁移决策

日期：2026-10-26。状态：DeerFlow 2.1 已作为普通只读投研默认运行时；模拟盘 AI 仍由原受限执行器运行。固定题集对比和长期恢复评测待完成。

## 决策

选择 **DeerFlow 2.1 作为普通投研 Agent 的默认运行时**，通过本地 Python worker 和 Unix socket 接入现有 FastAPI 应用。当前已切流，可用 `AI_AGENT_RUNTIME=legacy` 回退；固定题集对比仍待补。**金融数据、账户、回测、模拟订单、风控和现有前端继续由本项目持有**。DeepSeek 继续作为模型供应商；模型与 Harness 是两层独立选择。

不将整个项目迁入 DeerFlow，也不让通用 Agent 直接操作数据库、交易接口、任意 URL、文件系统或 shell。模拟交易维持独立的授权、校验和账本边界，第二阶段再迁移其研究与决策流程。

这是一项基于当前代码与官方文档的工程判断。已通过真实模型单标的端到端调用，但尚未做同模型、同数据、同题集的质量对比；若后续验证未达标，可回退并改进工具编排与评测。

## 现状和问题

| 现状 | 代码位置 | 对效果的影响 |
| --- | --- | --- |
| 每轮向模型发送完整工具清单，由模型选择调用，最多执行固定次数 | `app/ai_agent.py:66-90,123-186` | 工具选择受长清单干扰；复杂研究缺规划、阶段状态和跨步骤恢复 |
| 研究请求在 HTTP 请求里同步跑完，完成后才返回 | `app/main.py:811-864` | 没有逐步进度、取消或可恢复任务；进程退出可能留下 `running` 研究记录 |
| 引用检查仅测试答案是否包含任一证据 ID | `app/main.py:841-847` | 无法证明每个关键事实都有正确、同报告期的证据；引用错配也可能通过 |
| 模拟交易用内存 `asyncio.Task` 执行，重启把任务标记为 `interrupted` | `app/paper_agent.py:43-82`、`app/paper.py:141-149` | 订单账本保留，但研究步骤不能继续或精确重放 |
| 模拟订单已有授权范围、限额、幂等和交易规则 | `app/paper.py:291-316` | 这部分是必须保留的服务端权威边界，不应由通用插件替代 |

**诊断**：模型推理质量、行情和文档覆盖、检索质量、工具选择、证据核验、任务恢复都可能影响最终体验。换 Harness 本身不保证金融结论更正确，也不修复缺失数据。先用同一模型和固定数据集比较，才能判断迁移是否真的改善效果。

## 三个候选方案

| 方案 | 官方能力和接入形态 | 与本项目的匹配 | 主要代价 | 结论 |
| --- | --- | --- | --- | --- |
| [OpenClaw](https://docs.openclaw.ai/start/why-openclaw) | Gateway、聊天渠道、自动化、工具/Skill/插件；插件 SDK 能注册工具，Gateway 可提供兼容 API | 适合以后增加 IM/个人助理入口；当前核心是 Python 金融应用与受控研究流程 | 需要额外 Gateway 和 JS/TS 插件桥接；通用助理工具面需严格收窄 | 暂不作核心投研运行时 |
| [DeerFlow 2.1](https://github.com/bytedance/deer-flow/blob/main/docs/ARCHITECTURE.md) | Python/LangGraph 运行时，线程状态、流式输出、工具、MCP、Skill、子任务、沙箱；有 `DeerFlowClient` 嵌入接口 | 与 FastAPI/Python 工具和长流程研报研究最贴近；可只接入 Harness，不替换现有前端 | 依赖和配置较重；默认通用能力必须按金融 Agent 的权限收窄 | **已用于普通只读投研** |
| [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) | Cordis 插件架构；TS 插件注册工具；可用 Python SDK 驱动，但 SDK 会启动独立 `dsh` 运行时 | 插件隔离和可组合性强；适合作为单独研究工作台或外围助手 | 本项目的 Python 服务要跨进程/语言桥接；官方仍标注 developer preview 且可能有破坏性变更；`sdk-minimal` 默认有高权限 shell，不适合直接挂账户或订单 | 关注成熟度；不作为本轮全项目重构目标 |

依据：[DeerFlow 架构与嵌入客户端](https://github.com/bytedance/deer-flow/blob/main/docs/ARCHITECTURE.md)、[DeerFlow 自定义工具](https://deerflow.tech/en/docs/harness/customization)、[DeepSeek Harness 架构](https://deepseek-harness.github.io/deepseek-harness/en/reference/)、[DeepSeek Harness Python SDK](https://deepseek-harness.github.io/deepseek-harness/en/guide/python-sdk)、[OpenClaw 插件工具](https://docs.openclaw.ai/plugins/sdk-overview/tools-and-commands)。

### 为什么不用“整项目重构”为 Harness 插件

本项目的账户、行情时点、订单簿和撮合是确定性业务系统；Harness 管理的是模型驱动的研究步骤。把数据库和券商适配器搬进 Agent 插件，会让插件生命周期和模型工具权限侵入资金边界。推荐的所有权方向是：

```text
现有前端 → FastAPI（身份、授权、任务 API、证据/订单展示）
                  ├─ 行情/文档/回测/账户/模拟账本：现有确定性服务
                  └─ 投研运行时适配器 → DeerFlow：规划、工具选择、流式研究
                                                ↓ 仅调用受限工具
                                       现有服务的类型化只读接口

模拟交易：研究结果/结构化订单提议 → 服务端授权与风控 → 现有 Broker.submit
```

`Skill` 只承载研究方法和输出规范，不授予账户或交易权限；工具注册与服务端校验才决定可执行能力。DeepSeek、其他 OpenAI 兼容模型或本地模型可以在相同题集上作为模型变量比较。

## 目标运行形态（设计草案）

### 1. 结果与权限边界

- 用户结果：能完成多步骤投研，显示计划、工具进度、带时点与页码的证据和数据缺口；中断后可查询或继续研究。
- 持久变更：研究运行、步骤/工具事件、引用、成本与模型版本；模拟盘阶段才产生订单。
- 投研默认只读。账户数据只有显式选择账户后才可读取；模拟下单须有本轮 `AIRunRequest` 的账户、证券、金额和笔数授权。
- 实盘订单不作为 Agent 工具；现有实盘确认接口保持独立。
- 运行形态：**确定性业务驱动器 + 模型选择受限研究工具的编排器**。不宣称已达到任何外部 Harness 一致性等级；当前证据状态为 `UNSCORED`。

### 2. 角色和端口

| 角色/端口 | 本项目实现 | 约束 |
| --- | --- | --- |
| 用户与授权者 | FastAPI 身份会话、每轮研究/模拟授权 | 用户身份和账户范围来自服务端，不取自模型参数 |
| 研究 Worker | DeerFlow 线程中的模型 | 只看到本轮必要工具和最小上下文 |
| 事实验证器 | 独立于模型文本的引用/时点/报告期检查器 | 读取真实工具结果及原始文档片段；失败时退回“证据不足” |
| 队列与状态存储 | 持久运行表 + 事件表；DeerFlow checkpoint 映射 | 先写运行/步骤决定，再调用外部工具；重启后按状态恢复 |
| 工具适配器 | `ResearchTools` 拆成类型化、按任务分组的只读工具 | 不暴露 shell、文件写入、任意 HTTP、任意 SQL |
| 模拟交易 Gate | 现有 `Broker` 与本轮授权规则 | 以数据库事务、幂等键和订单记录为最终事实 |
| 用户展示 | 现有 `#/chat`、运行详情、证据卡 | 展示实际工具事件与订单状态，不信任模型自述 |

单机本地部署可让这些角色同进程，但逻辑检查不能由生成答案的模型自行判定成功。证据与订单是两个独立事实源。

### 3. 状态机与恢复

投研任务建议状态：`queued → gathering → verifying → complete`；任一步可进入 `failed`、`cancelled` 或 `needs_input`。`complete` 必须在验证器检查后写入。模型选择工具时，只能从本轮允许的工具集合中选；工具请求及参数先落事件表，再执行；结果和来源再落表。进程中断后根据最后完成的步骤重建上下文，不能凭模型口述跳过或重放有副作用的动作。

模拟盘单独保持 `authorized → researching → proposed → validating → submitted/declined → reconciled`。`submitted` 只能由 `Broker.submit` 的事务与幂等订单记录确认。对已提交订单的恢复先查账本，绝不重发一个新 ID。取消、失败和额度耗尽都应进入终态。

### 4. 资源和故障控制

- 每轮设工具次数、总时长、模型 token/费用、外部数据请求并发上限；超过预算停止并保存部分证据。
- 工具失败写明来源和时点；不允许模型用记忆补行情、财报数字或价格。
- 研究任务按 `run_id + step_id + tool_name + normalized_args` 去重缓存只读结果。订单继续由数据库唯一幂等键保证。
- 保留服务端停止入口，并检查停止后不会继续执行下一步；异常重启后任务有明确可恢复/已终止状态。
- 运行健康分开报告 API、模型供应商、数据源、后台执行器、订单 Gate；单纯 `/health` 返回 200 不代表 Agent 可用。

## 原规划的迁移顺序与验收

以下是接入前拟定的验证计划。实际执行已先将只读投研切为默认 DeerFlow 路径；未完成的评测和恢复能力仍按下列门槛验收。

### 阶段 0：建立同题评测基线

冻结 40–60 个本地题例与数据快照，覆盖个股、指数、三表同报告期、基金披露、研报逐页引用、新闻时点、数据缺失、工具错误和提示注入。使用**同一个模型、同样工具输出、同样题目**对比现有循环与候选运行时。记录：任务完成率、关键事实准确率、引用可追溯率、缺口说明、耗时、token/费用和失败恢复。人工复核样本；不得只用另一模型自评分。

### 阶段 1：只读垂直切片

先迁移“单只股票 + 指定研报”的研究：新运行时只拿 `search_instruments`、`get_stock_dossier`、`read_uploaded_document`、`get_instrument_research` 四类工具。保留原 API 返回格式，通过功能开关双跑但仅把旧结果展示给用户；新结果只入隔离研究记录。验证后再切换展示。此阶段不接账户、不接模拟订单、不启用通用 shell/文件写入。

验收门槛：固定题集上，引用 ID、页码、来源时点和报告期必须全部存在且指向实际返回片段；任何虚构行情数字或越权工具调用都失败。完成率和人工判定的事实质量须优于当前基线，或在同等质量下明显改善恢复/交互，且耗时和费用处于用户可接受范围。门槛以实际基线数值记录，不预设无依据的百分比。

故障测试：运行中杀进程并恢复；工具返回超时/空结果；研报注入“忽略规则”；同一请求并发重放；切换账户后继续旧线程；模型给出不存在的证据 ID。检查运行状态、权限拒绝和实际证据，不只看模型答案。

### 阶段 2：扩展研究与模拟盘

增加新闻、流动性、行业、基金、回测工具，并按任务类型动态装载。模拟盘先让运行时输出结构化提议和理由，再由服务端执行现有账户/白名单/额度/时点/幂等校验。保留已有一轮显式授权的产品语义。逐步验证恢复、停止和订单对账，最后移除旧的 `run_agent` 路径。

### 回退

保留现有研究入口适配器与数据库结构直到对比通过；新运行时故障时按功能开关退回旧路径。已有模拟订单永远以当前账本为准，回退不能重新提交或删除订单。

## 选择会改变的条件

- 如果目标变成通过飞书/Telegram 等渠道管理个人事务，OpenClaw 的渠道和 Gateway 优势会提高；仍需把金融权限留在本项目服务端。
- 如果目标变成高度可定制的桌面 Agent 产品，且团队愿意维护 TS/Cordis 插件与独立运行时，DeepSeek Harness 值得重新评估；先等插件 API 稳定并做安全隔离试验。
- 如果 40–60 题显示现有循环与 DeerFlow 质量接近，且恢复/流式体验收益不够抵消运维复杂度，则不迁移，直接改进工具分组、检索和验证器。

## 本次接入记录（2026-10-26）

- 仓库原先没有 DeerFlow 运行代码。现从 `dual_ai_voice_demo` 复用经校验的 DeerFlow 2.1.0 源码快照，放入 `vendor/deerflow/`；独立 Python 3.12 环境位于 `runtime/.venv`。
- `app/deerflow_service.py` 在本地私有 Unix socket 上预热运行时，`app/deerflow_bridge.py` 保留现有 FastAPI API；`AI_AGENT_RUNTIME=legacy` 可回退旧循环。
- `app/deerflow_tools.py` 仅注册服务器选定的投研工具。DeerFlow 授权提供者在组装和执行时拒绝内置文件工具、模拟下单工具及未选账户工具。
- Agent 提示和首页/自选入口已改为生成当日操作建议；没有可核验数据时明确建议观望。普通投研仍无自动下单能力。
- 对原先“本地没有日线”的缺口，DeerFlow 研究工具会对未缓存的六位 A 股尝试一次按需采集最近一年已完成日线；失败则保留缺口信息。已用 `CN:300308` 验证自动补数及 120 根日线指标证据。
- 日线证据增加最近 20 日最低价、收盘价区间和末日收盘价，供触发条件引用；提示要求价位标明来源和时点。午间休市的 `next_open` 由交易日历的午休结束时间给出。
- 本机真实模型验证：比亚迪单标的研究在 8 次工具调用内完成，返回 7 条证据和明确的“持有/观望”条件结论；DeerFlow 尝试调用内置 `read_file` 时被授权层拒绝。端到端 API 路径已完成一次成功运行。
- 本次不是原计划的双跑评测，也未实现跨进程断点恢复、逐 token 页面流式输出或模拟盘迁移。这些仍是后续验收项，不能把接入成功当作投研质量已提高的证明。
