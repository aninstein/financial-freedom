# 011 · 股票投研数据底座、研报检索与关联证据

状态：**分阶段实施中**。阶段 0 的 MySQL/Docker 部署与旧库逐表校验已完成，登录、模拟交易和模型研究的完整验收仍待进行；研报索引、分析快照与图谱评测仍待实施。调研和取舍见 [STORAGE_ENGINE_RESEARCH.md](../../docs/STORAGE_ENGINE_RESEARCH.md)。

## 目标与边界

让 Agent 在明确的证券、时间和来源范围内快速查询行情、财务事实、研报片段及它们的关系，输出可追溯、可复现的证据。llm-wiki 继续保存用户偏好、研究进度与历史会话记忆；其中的数字或结论不直接作为行情/财报事实。保持本地单用户、现有身份与模拟交易边界。

本增量**不**提供自由 SQL/Cypher、自动实盘交易、付费研报绕过、推断供应链关系自动变事实，亦不声称历史源已满足完整 PIT 回测。图数据库、向量库属于条件触发的后续 PoC。MySQL 是本轮确定的在线主库，SQLite 只作为一次性迁移来源。

## 用户故事和验收场景

### US1 · 可复现的数据分析

用户问“过去五年，某行业中现金流改善且波动率较低的股票有哪些”，系统使用版本化、确定性的计算作业筛选；结果包含 universe 定义、报告期/披露时点、价格口径、样本数、指标公式版本、数据快照 ID 和数据缺口。不能让模型自行心算或把未披露财报用于历史日期筛选。

验收：相同 `snapshot_id + query_version + 参数` 返回相同证券集合、排序和数值哈希；有修订时旧研究仍可重放；最新报价与历史分析快照各自标注截止时间。未满足最小样本量时返回 `insufficient_data`。

### US2 · 研报/财报的准确引用

用户问“这份研报对公司现金流和估值的主要论据及反方观点”，Agent 先检索经权限与时点过滤的段落，再按文档 ID、页码、段落偏移读取原文。对原文观点、结构化事实和模型推断分别标注。研报目录不当作已读全文。

验收：每条文档证据能定位到原文件、页码及片段哈希；删除原文后全文/向量索引、关联边和可访问证据一起失效，历史回答标注引用已撤销；中文两字常见金融词有检索覆盖；未取回的段落不能被引用。

### US3 · 关系探索

用户问“这些股票通过哪些公司、行业或研报风险因素相关”，系统只返回已确认或明确标记为候选的 1–3 跳路径，每条边附关系类型、有效期和原文出处。提及同一实体不等于存在经营/因果关系。

验收：路径显示每一跳的来源片段和审核状态；同名公司与证券代码消歧；`as_of` 之后才观察到的边被排除；超过深度/节点预算时返回截断标志而非静默省略。

### US4 · Agent 快速、安全查询

模型通过类型化只读工具请求证券、日期、指标或文档；服务端检查身份、范围、行数、时间、输出字节数和查询成本。禁止模型提交任意 SQL、文件路径、URL 或账本写入。缓存命中必须带快照与 freshness；数据源失败可返回旧证据，但必须标 `stale`。

验收：不存在通过研究工具访问其他账户或原始数据库的路径；超范围请求有明确错误；每个事实证据能回查其数据版本或原文片段。llm-wiki 召回文本只充当问题规划线索，事实须经过本工具重查。

## 功能要求

1. **统一标识和时间**：规范证券 ID（市场+代码）、实体别名与有效期；所有事实区分事件、报告期、发布时间、首次观察和入库时间。旧数据缺失时间信息时明确标记，不能补造。
2. **历史版本**：新增不可变的原始采集/修订记录和 `dataset_snapshot`；现有 `bars` 继续供当前页面读取，不能依赖会被 UPSERT 的行重放旧研究。新研究绑定快照，不允许同一个运行中悄悄换版本。
3. **财务事实**：只纳入有来源定位、单位/币种、会计范围和期别的数值。抽取候选需校验/审核，冲突版本并存；默认展示最新已确认版本并说明重述。
4. **文档分段**：按原页与章节切为有界段落，保留原文件哈希、页码、字符起止、标题、语言、报告期、发布/首次观察时间及权限。扫描 PDF 无文本时维持“需 OCR”的状态，不伪造片段。
5. **检索**：先结构过滤再全文召回，候选不足才用可选语义召回；结果合并、去重、重排后读取原文。MySQL `FULLTEXT ... WITH PARSER ngram` 使用双字切词，长词命中须原文精确复核，并用中文/英文/代码题集测召回及误报。索引构建/版本要可重跑。
6. **关系**：实体与边保存在 MySQL，边需 `relation_type`、方向、有效期、`known_at`、出处、审核状态。只允许白名单关系与上限 3 跳查询；候选关系不得在默认“已确认路径”中出现。
7. **列式快照**：从 MySQL 批量导出 Parquet 到 `data/analytics/`；manifest 包含 schema、计算/来源版本、分区文件哈希、行数、时间区间和发布状态。先写临时目录、校验，再原子发布；DuckDB 只读已发布快照。不能为每只股票每天建一个小文件。
8. **证据审计**：每次研究保存问题、工具名/参数、快照、源记录/片段 ID、引用定位、验证状态与撤销状态。`E001` 等展示 ID 可以每次运行局部编号，但后台要有稳定证据 UUID。
9. **删除与许可**：用户删除文档时清理派生索引、向量、事实候选及边；已发布分析快照若含受限原文衍生内容，需要标记不可用并重建。原始市场数据的留存/再分发遵从来源许可。

## 非功能与质量门槛

- 参考目标：单证券日线/财务 P95 ≤ 200 ms；限定证券与报告期的研报搜索 P95 ≤ 500 ms；10 年 × 5000 证券日线筛选 P95 ≤ 3 s；1–3 跳关系 P95 ≤ 500 ms。详见 [评测任务](tasks.md)。这些是验收目标，当前未实测。
- 正确性优先：PIT 泄漏 0、跨证券实体误合并 0、不可定位的文档引用 0（固定题集）；数值结果与确定性基线一致。中文召回率与页码准确率须记录基线并优于现有线性扫描方案；不能单靠延迟达标切流。
- 限制读写峰值；导出失败不会改变当前查询；服务重启可发现未发布临时工件并重试/清理。
- MySQL 持久卷、原件和 Parquet 派生文件包含私人投研数据；数据库仅在 Compose 内网开放，备份与密钥留在 Git 外。旧 SQLite 文件保留只读备份，迁移验证前不删除。

## 分阶段发布

0. **MySQL/Docker 基座**。参考 `dual_ai_voice_demo` 的 Compose 模式，启动 MySQL、一次性迁移、Web 与 Agent worker；旧 SQLite 两库只读导入并逐表校验。现已切换本机入口，仍需补齐身份/模拟账本并发和幂等行为的端到端验收。
1. **A：索引与证据**。扩展 MySQL schema 和导入管道；迁移旧文档页为片段；ngram 全文索引；财务事实/关系候选；只读 API；旧数据兼容并显示时间未知。
2. **B：分析快照**。导出/校验 Parquet；DuckDB 在后台只读运行同题对照；先在研究分析工具切读，不更改交易账本/页面当前行情路径。对照失败自动回退 MySQL 计算。
3. **C：优化决策**。固定题集测混合检索与多跳路径。如全文召回确有缺口，再试向量；如图遍历达到调研报告门槛，再试独立图数据库。每个新引擎须有删除传播、重建和回退设计。

## 与既有功能兼容

- `GET /api/v1/bars`、现有文档上传/读取接口和 AI 工具名称继续可用，内部可接新索引。历史返回增加可选元数据字段，不改变旧字段语义。
- 账户/模拟账本不导出到公共分析快照；若有授权账户研究，单次工具按既有显式授权读取并隔离。
- 旧 `dataset_manifests` 只证明当前采集批次，不升级为 PIT 版本；迁移时创建 `legacy_unverified` 标记。
- 本规格不直接改动 llm-wiki 内部实现；通过稳定的 Research API 和来源引用契约连接。
